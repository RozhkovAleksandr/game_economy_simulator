# Симулятор игровой экономики

Файл экономики → симуляция → таблица итогов и история в JSON.

## Запуск

```powershell
python simulator.py
python simulator.py config_A.json --output output/A.json
```

Без аргументов используются A и B, результат сохраняется в [results.json](results.json).
В `summary` — итоги по экономике и профилю, в `runs` — настройки и полная история игроков.
Повторный запуск перезаписывает файл результата.

Картинка из готового JSON:

```powershell
python -m pip install -r requirements.txt
python plot_results.py results.json --output results.png
```

[plot_results.py](plot_results.py) читает историю JSON и строит средний остаток золота по дням.
Повторная симуляция не запускается. Имена профилей берутся из файла.

## Как работает MVP

В [simulator.py](simulator.py) используются прямые проверки профиля:

- `saver` копит на целевой предмет и покупает его, как только хватает денег.
- `investor` сначала покупает улучшение, затем целевой предмет.

Один шаг — день: начислить награду → выполнить покупки → записать историю.
Улучшение увеличивает награду со следующего дня. Обе покупки возможны за один день.
После покупки цели расчёт продолжается до конца периода.
Проверка денег: `balance_before + earned - spent == balance`.

Функции: `validate` проверяет конфиг, `run_one` рассчитывает дни одного игрока,
`run_batch` проверяет конфиг и запускает игроков, `summarize` считает метрики,
`build_result` собирает JSON, `main` читает и сохраняет файлы.
Отдельного модуля стратегий и регистра алгоритмов нет.

## Настройки

В [config_A.json](config_A.json) и [config_B.json](config_B.json):

- `days` — число игровых дней.
- `players_per_profile` — одинаковое число игроков каждого выбранного профиля, сейчас 1.
- `profiles` — список, например `["saver", "investor"]`.
- `start_gold`, `action_reward` — стартовое золото и дневная награда.
- `item.name`, `item.price` — название и цена целевого предмета.
- `upgrade.name`, `upgrade.price`, `upgrade.reward_after` — улучшение и полная награда после него.
- `goal.type` — `own_item`; `goal.item` совпадает с `item.name`.
- `goal.by_day` — последний день покупки для успеха в срок; `name` — название экономики.

Прежнее `players` у каждого профиля задавало размер отдельной группы.
Это пригодится для моделирования разной доли профилей, например 800 накопителей и 200 инвесторов.
Сейчас случайности нет: игроки одного профиля полностью одинаковы, поэтому три повтора
не добавляют информации. Для MVP оставлен один общий параметр `players_per_profile`,
а настройки очередей, резервов и лимитов покупок убраны.

Защитный предел расчёта — 1 000 000 дней игроков:
`days × players_per_profile × число профилей`. Полные истории хранятся в памяти.

## Результаты

Каждый игрок содержит `goal_reached` (купил в срок), `goal_day` (день покупки или `null`),
`end_gold`, суммы доходов и трат, `session` (номер внутри профиля) и `history`.
В истории — баланс до и после дня, доход, траты, владение предметами и реальные действия:
`purchase` — покупка, `wait` — ожидание с недостающей суммой.

В `summary` шесть метрик: процент успевших в срок, процент купивших за весь период,
средний день покупки только среди купивших, средние доход, траты и конечное золото.
День покупки нужно читать вместе с долей купивших. Неуспех за период не доказывает недостижимость цели.

Для проверки вручную: инвестор A покупает меч в день 4 и заканчивает с 25 золота;
инвестор B — в день 5 с остатком 0. Накопитель в обоих вариантах покупает меч в день 5.
